# 群角色与机器人治理设计

## 目标

群角色只描述会话内权限，不复用公司级职位或系统管理员权限。机器人配置、自动化规则与敏感动作需要由群治理权限控制，普通成员只可使用已启用的能力。

## 角色

| 角色 | 来源 | 核心权限 |
| --- | --- | --- |
| `OWNER` | 创建群聊的用户 | 转移所有者、设置管理员、管理机器人和自动化、管理成员 |
| `ADMIN` | 由 `OWNER` 授予 | 管理机器人和自动化、管理成员；不可转移所有者或授予/撤销管理员 |
| `MEMBER` | 默认角色 | 发送消息、使用已启用机器人、提交审批 |

每个群必须且只能有一个 `OWNER`。不能将最后一个 `OWNER` 降级或移除；`OWNER` 不可由自己降级。私聊不使用群角色。

## 数据模型

角色保存于 `conversation_members.role`，使用枚举 `ConversationMemberRole`。历史成员没有角色时在读取时视为 `MEMBER`；数据库迁移后应回填：`conversations.created_by` 对应成员为 `OWNER`，其余为 `MEMBER`。

## 授权规则

```text
manageBot / manageAutomation / manageMembers: OWNER or ADMIN
manageAdmins / transferOwnership: OWNER only
useBot: MEMBER, ADMIN, OWNER (且群机器人已启用)
```

服务端必须在每个写入 API 执行授权；客户端隐藏按钮只是体验优化，不是安全边界。

## API

所有 ID 以字符串返回；请求中的用户 ID 不作为授权依据。

| Method | Path | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/groups/{conversationId}/members/roles` | 群成员 | 读取成员角色 |
| `PUT` | `/api/groups/{conversationId}/members/{userId}/role` | OWNER | 设置 `ADMIN` 或 `MEMBER` |
| `PUT` | `/api/groups/{conversationId}/owner` | OWNER | 转移群所有者 |

## 与机器人/自动化关系

- 群机器人配置由 `OWNER/ADMIN` 更新。
- 自动化规则创建、启停、查看执行记录由 `OWNER/ADMIN` 执行。
- 机器人调用和审批仍需校验会话成员关系；群角色不扩大跨会话或租户权限。
- 审计记录包含执行人和其当时的群角色快照（后续审计模型扩展）。
