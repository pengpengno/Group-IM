# 工作台技术开发手册

## 架构原则

工作台是导航聚合层，不是业务聚合服务。它不请求接口、不保存会话或会议副本；每张卡片仅触发明确的导航回调。这样 Web 与移动端可共享模块定义，同时遵守各自的 UI 生命周期和状态管理方式。

## Web / Electron

- 入口状态：`ActiveTab` 增加 `workbench`。
- 容器：`renderer/features/dashboard/Dashboard.tsx` 负责侧边栏入口与页面切换。
- 页面：`renderer/features/workbench/Workbench.tsx` 保持为展示组件，通过 `onNavigate` 回调跳转。
- 样式：`Workbench.css` 使用项目已有的浅色表面和蓝色主色，不依赖 Electron 原生能力，因此浏览器与 Electron 都可渲染。

## 移动端

- `ChatMainScreen` 的底部导航增加“工作台”。
- `WorkbenchUI` 仅接收导航 lambda，不访问仓库或 ViewModel。
- 会议与设置为独立路由；会话和联系人切换主屏的本地选项。新增入口时应继续遵循此分层。

## 新增模块步骤

1. 明确模块的现有归属、权限和降级路径。
2. 在两端分别新增卡片文案、图标与导航回调。
3. 不要在工作台复制目标模块的接口请求或状态。
4. 为新入口补充中文 KDoc/JSDoc，解释“为什么放在这里”以及状态归属。
5. 运行 Web 类型检查/构建和 Android Kotlin 编译。

## 编码与注释规范

- TypeScript、Kotlin 和 Markdown 统一保存为 UTF-8（无 BOM）。
- 业务可见文案使用正确中文，不把编码异常的字符串作为临时占位。
- 注释描述职责、状态归属与回退条件，避免重复代码本身可表达的内容。
- 生成目录（如 `dist-web`、`build`）不手工修改；修复始终落在源文件中。
